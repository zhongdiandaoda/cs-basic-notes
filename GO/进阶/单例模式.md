目的：在整个系统中只能出现类的一个实例，即一个类只有一个对象。

开发工具类库中的很多工具类都应用了单例模式，比例线程池、缓存、日志对象等，它们都只需要创建一个对象。  
如果创建多份实例，可能会带来不可预知的问题，比如资源的浪费、结果处理不一致等问题。单例模式的解决的痛点就是节约资源，节省时间从两个方面看。

1. 对于频繁使用的对象，可以省略创建对象所花费的时间，这对于那些重量级的对象而言，是很重要的.
2. 因为不需要频繁创建对象，GC压力也减轻了。

单例模式的缺点：简单的单例模式设计开发都比较简单，但是复杂的单例模式需要考虑线程安全等并发问题，引入了部分复杂度。

# 懒汉式

优势：延迟初始化，使用时才分配内存。

线程不安全：

```
//使用结构体代替类
type Tool struct {
    value int
}

//建立私有变量
var instance *Tool

//获取单例对象的方法，引用传递返回
func GetInstance() *Tool {
    if instance == nil {
        instance = new(Tool)
    }
    return instance
}
```

线程安全：

(每次加互斥锁，性能较差)

```
//使用结构体代替类
type Tool struct {
    value int
}

var lock sync.Mutex
//建立私有变量
var instance *Tool

//获取单例对象的方法，引用传递返回
func GetInstance() *Tool {
    lock.Lock()
    defer lock.Unlock()
    if instance == nil {
        instance = new(Tool)
    }
    return instance
}
```

双重锁校验：

```
//使用结构体代替类
type Tool struct {
    value int
}

var lock sync.Mutex
//建立私有变量
var instance *Tool

//第一次判断不加锁，第二次加锁
func GetInstance() *Tool {
    if instance == nil {
        lock.Lock()
        if instance == nil {
            instance = new (Tool)
        }
        lock.Unlock()
    }
    return instance
}
```

双重锁校验的缺点是可能会出现半初始化的问题，可以通过原子操作改善：

```
type Tool struct {
    value int
}

var （
    lock 		sync.Mutex
    done 		uint32
    instance 	*Tool
）

func GetInstance() *Tool {
    if atimic.LoadUint32(&done) == 0 {
        lock.Lock()
        if done == 0 {
            instance = new (Tool)
            atomic.StoreUint32(&done,1)
        }
        lock.Unlock()
    }
    return instance
}
```

通过sync.Once方法

```
type Tool struct {
    value int
}

var once sync.Once
var instance 	*Tool

func GetInstance() *Tool {
    once.Do(func() {
        instance = new(Tool)
    })
    return instance
}
```

# 饿汉式

优点：实现简单，不需要额外的比较判断。

```
type Tool struct {
    value int
}

var instance *Tool
func init() {
    instance = new(Tool)
}
func GetInstance() *Tool {
    return instance
}
```
